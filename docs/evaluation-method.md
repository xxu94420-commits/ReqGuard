# 评测方法与误差

`scripts/build_dataset.py` 保存逐条显式标注；`requirements.json`为评测输入。按每组3条的第三条划入test，共24 train/dev、12 test，覆盖各场景。分组模板近似，无法证明外部泛化；没有训练模型，train仅是规则开发集合。测试集在规则v1确定后执行，不用预测生成标签。

对每条的11个问题标签独立计数。TP=预测true且标签true；FP=预测true且标签false；FN=预测false且标签true。Precision=TP/(TP+FP)，Recall=TP/(TP+FN)，F1=2PR/(P+R)。分母零取0且输出支持计数。micro先合并所有标签的计数；逐标签结果另列。mixed_goals和unclear_scope在v1共享范围启发式，会产生相关误差，不能解释为独立能力。

测试结果：TP18、FP22、FN2，Precision 0.4500、Recall 0.9000、F1 0.6000。初始标签尚待人工复核，仅用于工程验证。风险只报告matches，不用于宣传整体“准确率”。结果附数据SHA256、规则版本、时间戳及错例。

误报：具体输入输出已说明但没有规则锚点时仍判信息不足；API标题不是完整契约；范围与多目标共享检测器会混淆。漏报：目标不可量化但有边界数字，被全局数值线索掩盖；CSV与禁止CSV、互斥保留期等语义冲突不在规则覆盖内；验收“成功”可能获得较高存在分。

LLM评测预留人工打分：每结论0不成立、1部分成立、2有证据且可行动；改写分别评价忠实性、完整性、可测试性0–2。每条至少两位复核者，记录模型/Prompt版本，隔离供应商响应与规则基准。当前没有真实供应商调用或人工评分，因此不报告LLM准确率。
