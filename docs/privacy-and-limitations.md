# 隐私、事实边界与MVP限制

需求原文是用户主动保存的业务数据；Java保存版本、评估派生结论与明确提交的交付证据。Python不持久化输入，不保存完整供应商响应；服务不打印密钥或供应商错误body。环境`.env`、本地凭据、数据库、缓存均排除Git和Docker上下文。

增强模式会将需求正文发往用户配置的供应商。不要输入未授权商业机密、个人敏感数据、访问令牌或密码。MVP没有自动识别/脱敏需求正文，不能承诺敏感数据过滤。只有标题、owner等元数据不发送到模型并不意味着正文安全。

没有身份认证、租户隔离、审计签名、业务删除或保留周期作业。Compose只绑定宿主127.0.0.1，仅用于个人演示；上线前必须实现身份、权限、TLS、备份、删除和保留策略。

规则判断词语与结构存在，不能证明业务正确。LLM逐字证据可保证可追溯但不能保证推理成立。置信度未校准，分数权重是设计假设，不是实证因果。人工反馈记录意见；不自动训练模型。生成模板含占位符时不能直接进入开发。

GitHub导入限固定api.github.com公开Issue读取，不含token，不写Issue/Commit/PR；未实现分页批量导入、限流缓存。交付证据链接与测试结果来自手工录入，未经第三方验证。复盘只陈述这些记录，不自动归因。

数据集与初始标签是AI辅助起草，独立人工复核待完成；小规模、中文模板相似，评测不能宣传广泛准确率。LLM真实供应商测试未进行，兼容性仅由mock测试验证。
