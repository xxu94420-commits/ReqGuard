# 原创质量评价标准 rubric-v1

每个维度使用证据分层：0 未发现线索；1 仅标题或短词；2 基本陈述；3 有细节；4 有验证线索；5 至少两处线索且文本≥120字。具体匹配见 `ai-service/app/rules.py`。这些分值是审查优先级，不是需求真实质量的客观测量。全局匹配可能误配不同段落，必须人工复核。

|维度|权重|0分示例|2分示例|3分细节|4分验证|5分补充证据|
|---|---:|---|---|---|---|---|
|背景完整度|5|无背景|目前存在问题|人工耗时|统计基线|基线与调研来源|
|用户与场景|8|无用户|用户导出|登录后使用|角色权限|租户与角色|
|目标明确度|9|无目标|目标改进|减少耗时|成功指标|分阶段目标|
|目标可衡量性|9|无指标|2秒|不超过2秒|测试窗口|多处量化条件|
|功能范围|8|无功能|支持导出|输入与输出|本期仅订单|明确范围与流程|
|非目标和边界|7|无边界|不支持跨租户|最大100条|超过时拒绝|空值和上限行为|
|验收标准|12|无验收|验收导出|Given/When|Then返回100条|多个可验证标准|
|可测试性|10|无测试|测试导出|给定输入|断言输出|多组测试条件|
|数据依赖|5|无来源|数据表|字段与格式|脱敏校验|保留与同步条件|
|接口及系统依赖|5|无依赖|接口API|版本与路径|超时契约|多依赖行为|
|异常与错误处理|7|无异常|失败处理|重试或返回|上限与记录|多个异常分支|
|风险说明|5|无风险|隐私风险|脱敏缓解|负责人验证|风险与监控措施|
|优先级|4|无字段|P1|因为影响|评审依据|多处排序理由|
|交付条件|6|无期限|交付日期|环境与负责人|测试通过|上线与回滚检查|

上表的1分均指仅列维度标题；实际3/4/5分由相应锚点、细节、验证和多证据逐级加分。结构化优先级已有时最低2分，但不能代表排序依据已确定。

总分 Σ(维度分×权重)/5；验收或可测试性≤1时上限59；发现登录冲突时上限49。验收、可测试性和目标占40%，因为它们直接影响交付判定；依赖与异常保护工程可执行性。分数<50高风险，50–79.9中风险，≥80低风险。LLM 不改变规则基准分，语义发现另列供人工确认，以确保可比较性。
