# 原创规则引擎 rules-v1

实现：`ai-service/app/rules.py`。14维元组包含锚点、细节、验证正则；输出评分与原文摘录。结构化优先级单独作为已知证据。所有规则确定性，无随机数和外部网络。

缺失：维度分<3产生 `missing_<dimension>`；词语未命中是一种审查线索，不是确定的业务缺失。量化锚点涵盖数字+单位。模糊词逐次检测：尽快、适当、友好、优化、较高、尽可能、等等、所有功能、全面升级。范围：全平台/全部系统/全面/一站式，或至少3个并列连接词。内部冲突初版仅识别匿名/无需登录与必须/仅登录共存，明确标记可能冲突。

测试检查包含测试/验收锚点与输入输出线索。规则会漏掉“验收：操作后成功”这种词语齐全但不可测的句子；不能把标题存在视为有效验收。全局细节和验证词匹配可能来自不相关段落，导致高分。这是v1已记录的局限，后续应按句子归属绑定证据，不通过测试集临时修补规则来虚高指标。

风险由质量分阈值与门槛决定，仅用于排序。规则置信度来自匹配明确程度，为设计常量，不是统计概率。缺失结论0.75、明确模糊词0.95、范围推断0.65、登录冲突0.85；仍全部需要人工确认。

规则模式输出改写模板与正向、异常、边界测试模板，保留待确认占位，不凭空填业务阈值。修改必须经人工保存到新版本，原文不被覆盖。
